# Public Generic Settlement Corpus v1

Status: implemented fixture/native evidence subset of issue #162. This is not
full PG-7 completion, a hosted-green declaration, or a publication decision.

## Scope and owning code

`tests/fixtures/public-generic-settlement-v1/cases.json` is the shared,
machine-readable `semaprax.public-generic-settlement-corpus.v1` manifest. The
library and native integration harnesses include the same bounded loader,
`tests/support/public_generic_settlement_manifest.rs`. The native harness still
uses `native::template::render_reference_provider`; the independent Python gate
composes the same C fragments and exact fixture binding preimages.

The admitted profile is explicitly `flat-owned-bytes-reference-fixture.v1`.
The descriptor fixture is not a descriptor reconstructed from a checked generic
export. The endpoint reverses each independent owned byte leaf. Two flat leaves
are not evidence for nested generic records or a Copy-scalar calling boundary.

The existing four-engine comparison covers the interpreter boundary model,
Core-Wasm in-process model, and compiled native C11 at O0/O2. Calling the Wasm
model does not establish execution of a compiled provider module. Production
provider ABI declarations, canonical logical-carrier schemas, generated-client
interfaces, diagnostics, and unsupported/unpublished standing decisions are
unchanged by this evidence extension.

## Manifest contract

The manifest is canonical sorted-key compact JSON, UTF-8/ASCII, followed by one
LF. Duplicate keys, alternate encodings, trailing documents, unknown keys,
unknown schema/profile/route/injection names, duplicate IDs, and stale carrier
digests are rejected. There are 22 cases: seven base shapes, fourteen individual
logical failure labels, and one compound execution/cleanup failure. Both Rust
harnesses now use the same two-leaf input for the compound case; their former
independently maintained tables did not.

Each case specifies its stable ID, bounded input recipes, optional primary and
cleanup injection labels, independently expected acceptance/status/endpoint
invocation, input/result carrier digests, and zero final-resource expectations.
Payload recipes are either lowercase hex or an exact repeated byte/length/count.
The loader admits at most 64 cases, 257 fixture leaves per case, 65,537 bytes per
leaf and 16 MiB + 1 expanded payload bytes per case. The extra one values permit
first-over-bound tests; they do not widen the provider's admitted limits. The
manifest itself is limited to 64 KiB.

Fixture input encoding is `u64le(leaf_count)` followed by each
`u64le(length) || payload`. The expected result reverses each leaf and uses the
same length framing. Native export includes a count header; the normalized
result digest excludes that header only after verifying its exact value.
This fixture wire form is not substituted for the full descriptor-bound
`LogicalCarrierFrame` codec.

Digest preimages follow the repository's domain/length framing convention:

```text
SHA256(ASCII(domain) || 0x00 || u64le(byte_length) || exact_bytes)
```

Domains for fixture carriers are the corpus schema followed by `/input` or
`/result`. Rendered digests are `sha256:` plus 64 lowercase hex digits. The Rust
loader reuses the repository's `digest_hex::LowerHex` formatter.

`native-expectations.json` pins the native trace labels, physical release
indices, allocation/child-handle peaks, endpoint count, secondary cleanup
statuses and overwrite counts for every case, bound to the exact manifest.
These are retained expectations, not output automatically regenerated by the
gate. Their trace observations are supplemented by direct C assertions of
left-to-right acquisition and exact reverse physical discharge. A fixture or
trace contract change requires an intentional, reviewed expectation update.
Peak byte counts remain target-local observations because native control-block
sizes depend on the target; O0/O2 on the same target must agree.

## Native fixes and observations

A known failure is selected before compensating input cleanup begins, without
adding a second terminal event. Previously, a leaf allocation failure followed
by injected cleanup failure could return status 11 instead of the original
allocation-failure status 10. A post-execution injection likewise cannot replace
an earlier endpoint failure. Conversely, when input cleanup genuinely fails
before a later result-handle allocation fails, cleanup correctly remains the
primary outcome. There is no hidden retry or re-execution.

Every result-payload rollback loop now discharges actual allocations in reverse
structural order. The same helper observes input and result leaf discharge,
including rollback paths that have no existing logical result-staging event.
It does not invent logical events for work the machine did not record.

The optional C observers are translation-unit-local macros, enabled only by the
settlement probe. Default provider builds expose no additional ABI symbols.
They measure successful provider allocations and requested bytes, registry
insertions/removals, entry into the actual fixture endpoint, actual physical
leaf releases, and later cleanup failures. A separate allocator fixture still
checks every provider malloc/free and final allocation balance.

Native peaks include actual provider/control/array allocations and count live
registry child handles. They are not equated with model heaps, which represent
root/leaf obligations differently. The legacy native normalized trace remains
label-only; the physical release channel carries `(direction, structural_index)`
with direction 0 for input and 1 for result. It contains no pointers, raw host
handles, payloads, clock values or process identifiers. Both channels are
bounded, and trace exhaustion fails the probe instead of accepting truncation.

The legacy native overwrite counter compares wire statuses. Contract failure
and cleanup failure both map to 11, unlike the models' distinct typed settlement
variants. That existing documented difference remains; separately recorded
secondary cleanup statuses prevent the new evidence from silently losing the
later failure simply because the numeric primary status is also 11.

The shared probe checks exact and one-byte-short result export, unchanged output
buffers after a capacity refusal, explicit release, null-release idempotence,
and rejection of a copied result handle immediately after release. It does not
claim to solve pointer-address reuse across later native allocations.

The native-only extension additionally executes 61 regression combinations:
22 real allocation-failure combinations (each of eleven allocation points,
alone and with cleanup injection), 35 input/execution plus cleanup-position
combinations, and four post-hoc result-staging rollback cases. These run in the
existing Cargo-generated native probe too, not solely in a separate script.
Native result-staging label injections remain post-hoc: the endpoint already
allocated the result. That is not an exhaustive target-neutral logical
result-allocation failure matrix.

## Portable evidence and replay

`scripts/public_generic_settlement_evidence.py` uses only Python's standard
library and an explicitly selected C11 compiler. It executes the shared probe
at O0/O2 and, when required, ASan/UBSan at O1. Every outcome must match the
manifest and retained native expectations; entire native observations must
also agree between optimization/sanitizer runs.

`semaprax.public-generic-settlement-evidence.v1` binds the manifest, retained
expectations and generated source bytes. Each ordered row includes the engine
and consumer route, exact descriptor/binding byte digests, actual compiled
provider-artifact digest, acceptance, actual endpoint invocation, primary and
secondary statuses, semantic-result/trace/release-order digests, target-local
peaks, final resources and overwrite count. Summary hashes use the same framed
digest convention with schema-specific `/manifest`, `/expectations`, `/sources`,
`/descriptor`, `/binding`, `/provider-artifact`, `/trace`,
`/release-order` and `/summary` domains as applicable. Result digests retain the
corpus `/result` domain so they directly match manifest expectations.

Canonical evidence is payload-free. Trace/release details are committed in the
expectation file and observed during execution; the summary retains their
hashes. Output contains no absolute paths or timestamps. Compiler-specific
binary digests are intentional: different provider binaries are different
subjects, even if their semantics agree.

Replay never treats a submitted digest as authority and never executes a binary
from submitted evidence. It first bounds and checks the public envelope, then
recompiles the trusted checkout and reconstructs the expected ordered rows.
Exact comparison rejects reminted semantic changes, wrong providers/engines/
cases, missing or unknown fields, reordered rows, changed counters and truncated
reports. The replay gate includes 25 structural and reminted semantic negative
controls. A changed toolchain/provider may legitimately invalidate an older
artifact; replay requires the same trusted subjects, not merely equal output.

## Focused gates

From the repository root:

```sh
cargo test --locked -p semaprax --lib public_generic_abi::carrier::settlement_corpus
cargo test --locked -p semaprax --test public_generic_native_adapter_v1 settlement_corpus
python3 scripts/public_generic_settlement_evidence.py --sanitizers --output target/pg-settlement
python3 scripts/public_generic_settlement_evidence.py --sanitizers --replay target/pg-settlement/evidence.json
cargo fmt --all -- --check
sh scripts/quality.sh full
```

`--cc` selects an explicit compiler; `CLANG` or `clang` is the default. A missing
compiler, failed build, assertion, sanitizer error, malformed output or replay
mismatch is a failing gate, never a skipped pass. The workflow selects the
portable sanitizer/replay gate on its existing Linux public-generic job; the
Cargo harness retains the existing cross-host selection. Configuration is not
hosted-run evidence.

## Remaining #162 closure work

The full issue still needs a real checked generic endpoint and compiler-derived
descriptor authority across the complete matrix, actual compiled Core-Wasm
provider execution, all four generated calling consumers driven by the same
settlement cases, nested records and every admitted Copy scalar, the complete
target-neutral per-leaf failure/commit/release matrix, and comparable complete
logical traces/peaks on every engine. Existing native/model trace differences
are not silently normalized away by this extension. Cross-host and hosted
promotion remain governed by the milestone and its separate gates.
