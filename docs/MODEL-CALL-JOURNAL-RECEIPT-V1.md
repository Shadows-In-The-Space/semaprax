# Model Call Journal Receipt v1

Status: local Rust evidence projection; no provider or invoice attestation.

`model_call_receipt::journal_projection` derives per-attempt receipts directly
from the generic live kernel's retained causal journal.
`model_call_receipt::source_projection` derives the same evidence shape from an
opaque, authenticated `RecoveredSourceCheckpoint`, including source retries and
priced/I/O profiles. These are read-only folds, not additional runtime logs.

The schema is `semaprax.model-call-journal-receipt.v1`. The enriched
[Model Call Receipt v1](MODEL-CALL-RECEIPT-V1.md) remains byte-compatible.
Its required host timestamps and monetary estimates cannot be reconstructed
from older journals; this separate projection preserves missing facts as JSON
`null` instead of pretending they were observed as zero.

## Evidence and verification

Each receipt binds `journal_profile`, `invocation_id`, the entire retained
`journal_chain`, `turn`, and `attempt`. Generic turns are zero-based with one
model attempt numbered 1. Source attempts retain their source-journal ordinals.
Request and response commitments retain the domains of their owning journal;
they are not interchangeable with the enriched receipt's payload commitments.
`source_prompt_digest` is absent for generic journals. Generic observation
commitments are copied only after checking their digest syntax.

`stage` records the model/decode boundary: `uncertain` for an unresolved durable
intent, `completed` for a recorded response, `decoded` for an admitted proposal,
`rejected` for refused decode, or `failed`/`cancelled` for recorded failure.
Decoded evidence grants no authorization. Tool outcomes and authorization rows
remain bound by the full chain, without being relabeled model outcomes.

`request_bytes`, `response_bytes`, `reserved_units`, `provider_reported`,
`timing`, and `cost` only carry journal-supported facts. A failed attempt's
`attempted_bytes = 0` sentinel is not a settled zero-length response or a zero
provider bill. Unrecorded provider identity, roots, task bytes, timestamps, and
invoice facts are not inferred. Source pricing remains in its declared integer
money units and is not silently converted to micro-units.

Raw tasks, observations, responses, credentials, and free-form refusal text are
excluded. Refusals use commitments. Digests of short or predictable payloads
can still be guessed; this is a payload-minimizing view, not an encryption or
secrecy guarantee. Journals and separately retained payloads remain private.

`project_kernel_calls` repeats the ordinary causal validator against an
independently retained `LiveInvocationId`, checks recorded response bytes against
their digest, and bounds input before journal encoding. It deliberately does
not accept `ValidatedJournal` as a trust token because that type's fields are
public. Empty journals emit no calls. Oversized inputs and unknown failure tags
fail closed. Both projectors cap receipt count before allocation and enforce a
4 MiB total rendered-byte limit. Generic input has a conservative 4 MiB escaped
encoding budget as well. `LiveKernelRun::model_call_receipts` uses that same path.

Source projection accepts only the opaque recovered checkpoint, whose owning
recovery route already checks causal order, binding, limits, usage and chains.
Neither projection proves a remote provider performed a physical call; an
unresolved persisted intent remains uncertain.

Receipts render key-sorted JSON with one trailing LF. Their digest is SHA-256
of those exact bytes, as required by Audit Capsule v1. `replay_kernel_calls`
and the source equivalent recompute the complete vector. The
`verify_*_receipt_bytes` APIs verify externally retained bytes by selecting the
caller-expected ordinal and comparing exact regenerated bytes. They do not
parse self-asserted receipt fields as authority, decode a fresh model answer,
contact a provider, dispatch tools, or publish an artifact. Independent proposal
decoding remains the separate enriched receipt replay contract.

## Audit Capsule association

`JournalCallReceipt::audit_object` constructs an `ObjectRef` of type
`model-call-receipt`, this schema, and its exact content digest. Its `session_id`
binding is the invocation identifier. The caller must supply a compatible
capsule subject; no deployment or target association is manufactured.
The regular capsule verifier still checks subject association and retained object
bytes. An object reference alone is not a complete agent-run capsule and provides
no signature or publication authority. Object ids include the receipt content digest, so different attempts and retained
checkpoint revisions have distinct ids.

## Focused executable evidence

Library tests under `model_call_receipt::journal_projection` execute the actual
generic kernel through offline fixtures, project two turns, check canonical
external-byte replay and audit bindings, preserve uncertain prefixes, and reject
response substitution, reordered journal rows, cross-turn receipt selection,
unknown failure tags, and oversized input. Source projection tests exercise
recovered source checkpoints. No hosted-provider or real-invoice claim is made.
